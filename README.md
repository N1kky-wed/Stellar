# Stellar: The Persistent Agentic Ecosystem

Stellar is a distributed, stateful operating system designed to transition AI from conversational interaction to **Autonomous Environment Agency**. It is architected for developers, security researchers, and systems engineers who require an AI that does not just "write code," but **provisions, mirrors, audits, and orchestrates** persistent, multi-container infrastructure.

Stellar operates as a self-correcting state machine with absolute authority over its underlying Docker compute clusters, unified by a production-grade networking fabric and a non-linear memory engine.

## 🧠 The Architectural Memory Engine

Stellar eliminates the "AI Amnesia" bottleneck through a proprietary dual-layered memory architecture designed for long-term project persistence.

### 1. The Ground-Truth Ledger
Every atomic action—every shell command, script execution, and file modification—is etched into a persistent SQL ledger. This allows Stellar to maintain a 100% accurate state of its environment across hundreds of turns, preventing the "state-drift" common in standard LLM sessions.

### 2. Paged Information Retrieval (Windowing)
To process industrial-scale telemetry (e.g., 10,000-line JSON responses or 50MB log files), Stellar utilizes a **Paged Memory Engine**:
*   **Metadata Compression:** Large outputs are automatically truncated into high-density summaries within the prompt.
*   **Autonomous Slicing:** The agent can independently decide to "scroll" through its history, retrieving specific line ranges or "slices" of past logs to find exact error signatures or data points without saturating the context window.

## 🌐 The Subdomain Fabric & Wildcard Routing

Stellar Project Hosting uses production-grade **Subdomain Fabric** and wildcard DNS routing. 

*   **Native Domain Routing:** Every project—whether built from scratch or deployed from a GitHub repository—is assigned a unique, permanent subdomain (e.g., `https://[project-slug].stellarai.live/`).
*   **Kernel-Level Interception:** A native Flask interceptor captures all incoming subdomain traffic, performs a real-time lookup in the Redis state-store, and routes traffic to the correct internal container port.
*   **Zero-Config Compatibility:** Absolute paths, React Routers, and API redirects work natively because each application believes it is running at the absolute root of its own domain.

## 🧪 Autonomous Container Orchestration

Unlike standard AIs that simulate environments, Stellar maintains direct, stateful control over the **Docker Engine**.

### 1. Multi-Deployment Clustering
Stellar can provision and manage multiple isolated containers simultaneously. It can deploy a frontend in one container, a backend in another, and a database in a third, then configure the networking environment to allow them to communicate across the internal bridge.

### 2. Remote Repository Ingestion
The agent can ingest any public or private GitHub repository from scratch. It clones the code, analyzes the `package.json` or `requirements.txt`, provisions a container with the correct runtime (Node, Python, Go, Rust), and executes the build pipeline autonomously.

### 3. Self-Healing CI/CD Loops
If a deployment fails, Stellar enters a recursive self-correction loop. It reads the build logs via its **Paged Memory**, identifies the missing dependency or syntax error, patches the source code, and triggers an automatic redeploy.

### 4. Manual Logic Snapshots
If a developer manually edits code within a container, Stellar **snapshots** those changes back to its central ledger. This ensures that human-written logic is never lost and is correctly merged during subsequent AI-driven iterations.

## 📓 High-Impact Use Cases

### I. Multi-Repo Infrastructure Orchestration (The "Landing Cluster")
**Goal:** Deploy three unique landing pages (Gym, Restaurant, Space) simultaneously.
*   **The Workflow:** In a single conversational turn, Stellar provisions three independent virtualized environments. It injects unique custom stacks into each, configures the internal network listeners, and deploys them to three separate subdomains. It then generates a technical walkthrough of the cluster architecture.

### II. Legacy "Rescue & Redeploy" Loop
**Goal:** Deploy a legacy Node.js app crashing due to outdated dependencies.
*   **The Workflow:** Stellar provisions a container and clones the remote code. It attempts a build, identifies a version error in its paged logs, autonomously upgrades the container’s runtime, patches the source, and verifies the site success at its unique subdomain—all without user intervention.

### III. Adversarial Security Auditing (Red Teaming)
**Goal:** Identify saturation points and logic flaws in a production grading engine.
*   **The Workflow:** Stellar identifies target API endpoints and fires a "Saturation Bomb" (1,000+ concurrent requests). It identifies the worker pool depth and verifies the presence of AST/Hash caching mechanisms by observing `runtime_ms: 0` on duplicate submissions, providing a detailed architectural bottleneck report.

### IV. Recursive Institutional Mirroring
**Goal:** Create a functional, hosted clone of a complex academic portal.
*   **The Workflow:** Stellar performs a recursive crawl of a target domain (e.g., a university site), mirrors ~100MB of assets (HTML/CSS/JS/Images), restructures them for a managed root, provisions a dedicated server, and re-hosts the clone on the Subdomain Fabric for archival or adversarial review.

### V. Multi-Stage Quantitative Research & PPT Delivery
**Goal:** Synthesize a 50-page technical paper and a 15-slide executive deck.
*   **The Workflow:** Stellar performs recursive web-grounding and file analysis, rendering interactive SVG visualizations natively. It then uses its **Presentation Engine** to render a `.pptx` where each slide is a high-resolution infographic, allowing for AI-driven visual regeneration.

### VI. Automated Infrastructure Reconnaissance
**Goal:** Isolate verified API keys and internal logic from a minified web asset.
*   **The Workflow:** Stellar uses its persistent sandbox to crawl a target site and identify JavaScript bundles. It writes and executes a targeted extraction script to de-minify the code. Utilizing its **Slicing Ability**, the agent parses through massive source files to isolate the specific logic required to authenticate with a private API.
